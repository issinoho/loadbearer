Know which machine is faster — and why.

loadbearer benchmarks a machine's CPU, memory, disk and network stack — and its GPU where there is one — scores every measurement against a shared reference baseline, and grades each component and the whole machine on an S‑to‑F scale. Point it at two laptops and it tells you which one wins, by how much, and what's holding the other back. A sustained‑load test shows how much speed each one keeps once it heats up.

What it does

A benchmark that answers a question, not just prints numbers

Raw MiB/s and Mops/s don't tell you whether laptop A beats laptop B. loadbearer turns them into a grade, a verdict, and a reason.

One graded answer per machine

CPU, memory, disk and network each get a score against the baseline (1000 = the mean of a small fleet of real machines) and a letter grade. A profile-weighted geometric mean of CPU, memory and disk becomes one overall grade, with a plain-language note on what moved it. Network, the GPU (FP32 + VRAM bandwidth, via OpenCL), battery health, and the sustained-load test are shown alongside — OS, optional hardware, wear, cooling — so they don't skew the grade. When the CPU or GPU model is in the reference table, a vs typical hardware line says whether it's performing to spec for its model — also ungraded.

Head-to-head, in one sentence

loadbearer compare a.json b.json reads the raw metrics from two runs and says: "dev-desktop leads by 68% overall (ahead on cpu +90%, memory +55%)." Baseline-independent, so it holds even across tool versions — and loadbearer score re-grades an old run against a new baseline without re-running it.

A method you can check

Fixed-time throughput measurement, medians with confidence flags from run-to-run spread, geometric means throughout, and a documented baseline you can regenerate from your own hardware. No hidden weighting — it's a few constants in the source.

Honest and self-contained

One static binary, no runtime. No network calls — the network test is loopback only. Disk reads bypass the OS page cache (O_DIRECT / FILE_FLAG_NO_BUFFERING). Workloads are reproducible with --seed.

See it

The whole thing is a terminal

An interactive run shows a live TUI, and compare opens a scrollable coloured view; piped or scripted, both fall back to plain text or JSON. info, soak and mem are plain diagnostics. Here's the plain output.

Examples

A few things you'd actually type

bash
$ loadbearer run                         # grade this machine (TUI)
$ loadbearer run --output me.json        # ...and save the result
$ loadbearer compare me.json them.json   # which machine wins, and why
$ loadbearer soak                        # does it throttle under a long load?
$ loadbearer mem                         # what's using RAM (ps_mem-style, PSS)
$ loadbearer score me.json --baseline ref.toml  # re-grade, no re-run
$ loadbearer run --json | jq .overall    # for scripts and CI gates
$ loadbearer run --only cpu,memory       # skip the disk write
$ loadbearer baseline runs/*.json > ref.toml  # recalibrate to your fleet

Profiles (--profile dev-workstation, content-creation, server) reweight the components for a workload. loadbearer run --soak folds the sustained-load test into a full assessment. A real link test between two machines: loadbearer net-server on one, loadbearer run --net-target HOST:PORT on the other. Every run writes a plain-text diagnostic log (--log-file, --no-log, --log-level) for after-the-fact troubleshooting.

Install

Download a binary, or build it

Every tagged release ships a self-contained loadbearer.exe for Windows and a Linux tarball, built from the same source by CI. macOS on Apple Silicon builds and runs from that same source.

🪟 Windows (x86-64)

Unzip and run loadbearer.exe from a terminal. Windows builds are Authenticode-signed via SignPath.io's free programme for open source (certificate by the SignPath Foundation); until the certificate builds reputation, SmartScreen may still prompt (More info → Run anyway) and Smart App Control can block it — run it on a machine without SAC, or build from source. Each release publishes SHA256SUMS.

Download .zip

🐧 Linux (x86-64)

Extract the tarball and run ./loadbearer, or install from source:

cargo install --git https://github.com/issinoho/loadbearer --locked
Download .tar.gz

🍎 macOS (Apple Silicon)

No pre-built binary yet — build from source with the same command. All five components work, GPU via Apple's OpenCL framework. The CPU aes_gcm / sha256 figures read low (no Arm crypto instructions in the build) and disk I/O is buffered, both noted in the result.

cargo install --git https://github.com/issinoho/loadbearer --locked
macOS notes

🛠️ From source

Needs a recent stable Rust toolchain. On x86, for CPU kernels that use your machine's widest vectors (on Apple Silicon a plain release build is already native):

RUSTFLAGS="-C target-cpu=native" \
  cargo build --release
